# 患者查询接口

更新日期：2026-11-15。

面向本系统患者档案的院内查找场景，支持按姓名查找、编号或电话定位、组合筛选和分页。沿用现有 Flask / SQLAlchemy 结构和 JWT 登录鉴权，不需要修改数据库表结构。

## 分页查询

`GET /api/patient/search`

请求头：`Authorization: Bearer <token>`。现有有效账号均可查询，权限与患者列表接口一致；未登录、账号停用或登录失效返回 HTTP 401。响应包含 `Cache-Control: no-store`。

| 参数 | 类型 | 默认值 | 规则 |
| --- | --- | --- | --- |
| `keyword` | 文本 | 空 | 最多 50 字符；姓名包含该文本，或患者编号、电话等于该文本，满足其中一个即可 |
| `name` | 文本 | 空 | 姓名包含该文本，最多 50 字符 |
| `patient_no` | 文本 | 空 | 患者编号完整匹配，最多 50 字符 |
| `phone` | 文本 | 空 | 电话完整匹配，最多 20 字符 |
| `gender` | 文本 | 空 | `男`、`女`、`其他`、`未知` |
| `age_min` | 整数 | 空 | 最小年龄，0～150，包含边界 |
| `age_max` | 整数 | 空 | 最大年龄，0～150，包含边界，不能小于最小年龄 |
| `page` | 整数 | 1 | 1～2147483647 |
| `page_size` | 整数 | 20 | 1～100 |

各参数去除首尾空白，空值忽略；分页空值使用默认值。不同筛选条件之间为 AND；`keyword` 内三个字段之间为 OR。年龄按档案保存的年龄筛选；设置任一年龄边界时，不包含年龄未填写的患者。`%`、`_`、`/`、`\` 均按实际字符检索，不作为通配符。重复参数、未知参数、非法性别、文本超长或数值越界返回 HTTP 400，避免参数写错后被静默忽略。

结果按患者 `id` 降序排列。总数为所有条件筛选后的数量；无匹配和超过末页均成功返回 `items: []`，保留所请求的页码；无匹配时 `pages` 为 0。同名患者保留各自的 `id`、`patient_no`，后续查看详情使用选中记录的 `id`。

PowerShell 调用示例，查询姓名包含“张”的 60～80 岁男性患者：

```powershell
curl.exe --get "http://localhost:8081/api/patient/search" `
  --header "Authorization: Bearer <token>" `
  --data-urlencode "name=张" `
  --data-urlencode "gender=男" `
  --data-urlencode "age_min=60" `
  --data-urlencode "age_max=80" `
  --data-urlencode "page=1" `
  --data-urlencode "page_size=20"
```

成功响应示例（合成数据）：

```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "items": [
      {
        "id": 37,
        "patient_no": "DEMO-00037",
        "name": "张某某",
        "gender": "男",
        "age": 65,
        "phone": "13800000001",
        "create_time": "2026-11-15 09:00:00"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20,
    "pages": 1
  }
}
```

查询列表只读取并返回 `id`、`patient_no`、`name`、`gender`、`age`、`phone`、`create_time`，不返回地址和既往病史；字段未填写时保留原有空值。

## 患者详情

`GET /api/patient/detail/<id>`

鉴权方式同上，`id` 为系统内患者主键，不是患者编号。成功时 `data` 返回该患者完整档案，字段与旧列表单条记录一致，在上述查询字段之外包含 `address`、`medical_history`。不存在或超出数据库主键范围返回 HTTP 404。详情不附带病历，也不按姓名自动选择患者。

```powershell
curl.exe "http://localhost:8081/api/patient/detail/37" `
  --header "Authorization: Bearer <token>"
```

错误格式与项目其他接口一致，HTTP 状态码和 `code` 一致：

```json
{
  "code": 404,
  "msg": "患者不存在",
  "data": null
}
```

## 前端调用与兼容

`frontend/src/api/patient.js` 提供调用函数，现有请求拦截器自动附带登录令牌：

```js
const result = await searchPatients({ name: '张', page: 1, page_size: 20 })
const { items, total, pages } = result.data
if (items.length) {
  const detail = await getPatientDetail(items[0].id) // 实际页面按用户选中记录调用
}
```

“患者管理”页面上方提供患者查询表单：输入姓名、完整患者编号或电话，可结合性别、年龄范围查询，支持 Enter 提交、重置、分页及每页条数切换。查询列表的查看按钮打开完整患者详情；编辑前也读取完整档案，防止列表中未返回的地址、既往病史在保存时丢失。保存、删除或撤销后按当前查询条件重新加载列表，删除末页最后一条时自动退回有效页。电子病历页右上角提供“查询患者”入口。

旧 `GET /api/patient/list` 保持数组响应，病历选择等现有调用继续使用旧列表。Docker 运行模式需重新执行 `./start.ps1`（独立演示使用 `./start.ps1 -Demo`）构建并加载更新。

本接口读取项目现有患者档案，尚未对接医院 HIS/EMR；患者编号按当前 `patient_no` 定义，不代表已接入就诊卡、门诊号、住院号或身份证查询。若接入具体医院，需根据其接口字段、身份标识和访问权限约定适配。
