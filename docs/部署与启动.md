# 智慧医疗平台部署与启动

更新日期：2026-10-16。以下命令在 Windows PowerShell 中执行。

项目概览与目录说明见[README](../README.md)。本文中的相对命令路径以项目根目录为起点。

## Docker 启动与重启

安装并打开 Docker Desktop，使用 Linux 容器，等待引擎就绪：

```powershell
Set-Location 'D:\Thesis\thesis medical'
docker version
docker compose version
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
docker compose up -d --build --wait --wait-timeout 240
```

打开 http://localhost:8080。Docker 同时提供前端和后端，不必另开前端开发服务器。首次构建需要网络，构建时长不受就绪等待的 240 秒限制。

电脑重新开机后，先启动 Docker Desktop，再执行：

```powershell
Set-Location 'D:\Thesis\thesis medical'
docker compose up -d --wait --wait-timeout 240
```

仅重启应用：

```powershell
docker compose restart app
docker compose ps
Invoke-RestMethod 'http://localhost:8080/api/health'
```

代码或依赖修改后重新执行带 --build 的启动命令。仅修改 .env 时执行 docker compose up -d；单纯 restart 不会加载新的容器环境变量。

## 登录和修改密码

全新数据库的默认初始账号为 admin，初始密码为 Admin123456。首次部署前可在 .env 设置 DOCKER_ADMIN_USERNAME 和 DOCKER_ADMIN_PASSWORD。

这两个变量只用于创建缺失账号，已有账号不会因修改配置或重启而重置密码，也不能用于查看当前密码。

登录后点击右上角“修改密码”，输入原密码及两次新密码。新密码需 8～128 个字符，成功后重新登录，所有旧登录凭证立即失效。旧版明文密码会在成功登录时自动转换为哈希，原密码保持有效。

忘记密码时，在项目目录运行以下交互式命令；输入密码不会回显：

```powershell
docker compose exec app python -m deploy.reset_password admin
```

## 配置环境

.env 保存在项目根目录，不应公开或提交。AI 功能需要：

| 变量 | 用途 / 默认值 |
| --- | --- |
| DEEPSEEK_API_KEY | 对话服务密钥 |
| DEEPSEEK_BASE_URL | https://api.deepseek.com/v1 |
| DASHSCOPE_API_KEY | 向量服务密钥 |
| DASHSCOPE_BASE_URL | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| DOCKER_HTTP_PORT | 主机网页端口，默认 8080 |
| DOCKER_MYSQL_DATABASE | 容器数据库，默认 smart_medical |
| DOCKER_MYSQL_USER | 容器业务用户，默认 medical_app |
| DOCKER_MYSQL_PASSWORD | 容器业务数据库密码 |
| DOCKER_MYSQL_ROOT_PASSWORD | 容器数据库管理员密码 |
| SECRET_KEY | 留空自动生成并持久化 JWT 签名密钥 |

已有 MySQL 数据卷不会因更改 MYSQL 初始化变量而自动改变数据库密码，应先在数据库中执行对应维护操作再同步配置。

没有 AI 密钥仍能使用登录、患者和病历功能。进程环境变量优先于根目录 .env。Docker 数据库和本机数据库独立，不自动导入本机旧数据。

## 本机分别启动后端和前端

准备 Python 3.11、Node.js 22、MySQL 8.0。先创建 UTF-8 数据库 smart_medical，并在 .env 配置 MYSQL_HOST、MYSQL_PORT、MYSQL_USER、MYSQL_PASSWORD、MYSQL_DATABASE。

后端 PowerShell 窗口：

```powershell
Set-Location 'D:\Thesis\thesis medical'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-docker.txt
$env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
$initialPassword = Read-Host '首次创建管理员的密码' -AsSecureString
$env:BOOTSTRAP_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $initialPassword).Password
.\.venv\Scripts\python.exe -m deploy.start
```

上述环境变量只在当前窗口有效，仅在账号不存在时初始化。再次启动只需执行最后一行。本机维护密码可执行：

```powershell
.\.venv\Scripts\python.exe -m deploy.reset_password admin
```

前端另开 PowerShell 窗口：

```powershell
Set-Location 'D:\Thesis\thesis medical\frontend'
npm ci
npm run dev -- --host 0.0.0.0
```

打开 http://localhost:5173；Vite 将 /api 代理到 127.0.0.1:5000。关闭窗口或 Ctrl+C 会停止对应本机进程。纯开发后端也可执行 .\.venv\Scripts\python.exe backend/app.py，但不会自动创建管理员。正式 WSGI 工厂启动方式为 waitress-serve --call --listen=0.0.0.0:5000 backend.app:create_app。

在 PyCharm 中运行 backend/app.py 后，也可直接打开 http://127.0.0.1:5000 查看已构建的前端。本机和 Docker 使用不同数据库，账号及业务记录可能不同。启动日志中的“历史数据待核对”是警告，服务可正常启动；病历页会标识缺失患者的旧病历。核对前不应随意重分配或删除这些病历。

## 手机访问

手机与电脑连接同一可互访的局域网，在电脑执行 ipconfig，找到 Wi-Fi IPv4 地址。手机访问 http://电脑IPv4:8080；手机中的 localhost 指向手机本身。地址可能随网络变化，移动数据和访客 Wi-Fi 通常无法访问电脑。

容器已绑定 0.0.0.0。防火墙放行需由电脑管理员确认；本次未更改防火墙规则。

## 状态、日志、停止和备份

```powershell
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 mysql
docker compose down
```

down 保留数据；不要加 -v，-v 会删除数据卷。三个卷分别保存 MySQL、知识库、随机 JWT 密钥。

有 Python 环境时备份：

```powershell
.\.venv\Scripts\python.exe deploy/backup.py
```

备份保存到 backups/时间戳，含 mysql.sql、chroma_db、存在时的 instance 及 manifest.json。脚本短暂暂停应用写入，备份后自动恢复；失败会报错。备份包含敏感业务数据和可能的签名密钥，应限制访问。恢复时需停应用，将 SQL 导入目标数据库并恢复知识库和 instance，先验证备份后操作；不要直接覆盖运行中的卷。

## 回归验证

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Set-Location frontend
npm test
npm run build
npm run test:e2e
npm audit
```

浏览器测试使用已安装的 Microsoft Edge 和独立 SQLite/Chroma 测试目录，不操作现有业务数据。真实 AI 连通性测试从项目根目录执行 .\.venv\Scripts\python.exe -m deploy.check_ai，仅发送合成测试文本，不写入知识库。
