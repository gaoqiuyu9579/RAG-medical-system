# 部署与启动

更新日期：2026-11-12。以下命令以 Windows PowerShell 和当前目录 `E:\Thesis\thesis medical` 为例；复制项目到其他目录时改用实际路径。

## Docker：日常使用

打开 Docker Desktop，使用 Linux 容器，等待引擎就绪：

```powershell
Set-Location 'E:\Thesis\thesis medical'
.\start.ps1
```

访问 [http://localhost:8080](http://localhost:8080)。脚本自动创建缺失的 `.env`，从当前源码构建前后端，启动 MySQL 与应用并等待健康检查。首次构建需要联网；240 秒是服务就绪等待时间，不包含镜像构建。

若系统禁止执行脚本，执行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`，只对当前进程生效。

```powershell
.\start.ps1 status
.\start.ps1 logs
.\start.ps1 stop
```

停止保留数据库、知识库和签名密钥卷。再次启动、更新源码或修改 `.env` 后，都重新执行 `.\start.ps1`。

不使用脚本时的等效命令：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
docker compose up -d --build --wait --wait-timeout 240
docker compose ps
Invoke-RestMethod 'http://localhost:8080/api/health'
```

```powershell
.\start.ps1 -Demo
.\start.ps1 status -Demo
.\start.ps1 logs -Demo
.\start.ps1 stop -Demo
```

演示地址为 [http://localhost:8081](http://localhost:8081)，初始账号 `admin`、密码 `Admin123456`。项目名为 `smart-medical-demo`，使用独立数据卷，首次向空库写入 12 位合成患者和 56 份近 30 天病历。已有患者或历史病历时不重复导入。

演示参数通过本次 PowerShell 进程传给 Compose。正常部署使用 `.env` 配置及原数据卷。两种部署均从当前源码构建，并使用同一份 `.env` 中的 AI 服务配置。

## 账号和配置

全新正常部署的初始账号默认为 `admin`、密码 `Admin123456`，可在首次启动前设置 `.env` 中的 `DOCKER_ADMIN_USERNAME` 和 `DOCKER_ADMIN_PASSWORD`。已有账号不会因修改初始化变量而重置密码。

登录后通过右上角修改密码。忘记正常部署密码时执行：

```powershell
docker compose exec app python -m deploy.reset_password admin
```

演示部署使用 `docker compose --project-name smart-medical-demo exec app python -m deploy.reset_password admin`。

| `.env` 配置 | 用途 / 默认值 |
| --- | --- |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` | 对话服务；默认地址 `https://api.deepseek.com/v1` |
| `DASHSCOPE_API_KEY` / `DASHSCOPE_BASE_URL` | 向量服务；默认地址 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `DOCKER_HTTP_PORT` | 正常部署端口，默认 `8080` |
| `DOCKER_MYSQL_DATABASE` | 容器数据库名，默认 `smart_medical` |
| `DOCKER_MYSQL_USER` / `DOCKER_MYSQL_PASSWORD` | 容器业务数据库用户及密码 |
| `DOCKER_MYSQL_ROOT_PASSWORD` | 容器数据库管理员密码 |
| `DOCKER_SEED_DEMO_DATA` | 正常部署向空库导入合成资料，默认 `0`；演示模式自动设为 `1` |
| `SECRET_KEY` | 留空时自动生成并持久化 JWT 签名密钥 |

未配置 AI 密钥时，账号、患者、病历和统计功能仍可使用。修改 `.env` 后运行启动脚本以重建容器环境，单纯 `docker compose restart` 不会加载新变量。已有 MySQL 数据卷的数据库密码需要通过数据库维护命令修改，初始化变量不会替已有数据库改密码。

## 本机开发

准备 Python 3.11、Node.js 22、MySQL 8.0，创建 UTF-8 数据库 `smart_medical`，在 `.env` 配置 `MYSQL_*`。在两个 PowerShell 窗口分别启动。

后端：

```powershell
Set-Location 'E:\Thesis\thesis medical'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
$initialPassword = Read-Host '首次创建管理员的密码' -AsSecureString
$env:BOOTSTRAP_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $initialPassword).Password
.\.venv\Scripts\python.exe -m deploy.start
```

已有虚拟环境时可跳过创建和安装。已有账号不受初始化变量影响；日常启动后端执行最后一行。

前端：

```powershell
Set-Location 'E:\Thesis\thesis medical\frontend'
npm ci
npm run dev
```

访问 [http://localhost:5173](http://localhost:5173)。Vite 将 `/api` 转发到后端 `5000` 端口。需要由后端直接提供前端页面时，先执行 `npm run build`，再访问 [http://localhost:5000](http://localhost:5000)。本机开发数据库与 Docker 数据库独立。

## 验证、备份和手机访问

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m deploy.verify_deployment --restart
.\.venv\Scripts\python.exe -m deploy.verify_deployment --project smart-medical-demo --url http://127.0.0.1:8081
.\.venv\Scripts\python.exe deploy/backup.py
```

第二条用于已启动的独立演示服务。修改正常部署端口后，给验证命令添加 `--url http://127.0.0.1:实际端口`。

验证脚本核对容器内 Python 源文件与工作区一致、前端资源可访问、统计接口返回 7/30/90 天数据、接口鉴权有效。`--restart` 还检查应用重启后原登录凭证继续有效。备份默认针对正常部署，保存到 `backups/时间戳/`，包含 SQL、知识库和签名密钥；执行时短暂暂停应用写入。

手机与电脑连接同一局域网，执行 `ipconfig` 查看电脑 IPv4，手机访问 `http://电脑IPv4:8080`，独立演示用 `8081`。Windows 防火墙需允许所用端口。不要使用 `docker compose down -v` 停止日常服务，因为它会删除数据卷。
